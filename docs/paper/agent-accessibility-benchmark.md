# Do Accessibility Defects Break AI Web Agents? A Pre-Registered Benchmark

*Draft for arXiv (Week 18, plan v2 D1). Sections 5–6 are filled only from the
pre-registered run (`docs/agentbench/results-v1.md`, generated by
`eval/agentbench/report_v1.py`). Every number not yet measured is marked
**[RUN]** — nothing in this draft is estimated.*

Authors: Rohan Arekatla, Nikhil Chunduri

## Abstract

AI web agents increasingly perceive pages through the accessibility tree — the
same interface screen readers use. Practitioners assert that WCAG defects
therefore hurt agents, but no controlled measurement exists. We report the
first pre-registered study of how injected WCAG defects change web-agent task
success, across three agent types (accessibility-tree-only, DOM/visible-text,
and a screen-reader simulation that perceives only announcements and acts only
by keyboard) and **[RUN]** models (local open-weight and frontier). Defects are
injected at page load, verified by a deterministic checker to be present,
pixel-invisible, and the only change, and task success is decided by
deterministic evaluators — no model judges any outcome. **[RUN: headline
effect sizes with intervals.]** We release the harness, tasks, injectors,
pre-registration, and data.

## 1. Introduction

- The accessibility tree became an agent interface: Playwright MCP is
  tree-based; Chrome documents a well-formed tree as how agents understand a
  page; OpenAI states ChatGPT Atlas reads ARIA (sources:
  `docs/research/agent-accessibility-2026.md`).
- Gap: work on agent observation spaces (LCoW, observation-reduction studies,
  VisualWebArena) shows that *representation* matters, never that a specific
  WCAG defect does, by how much, or for which agent.
- Contributions: (1) a pre-registered, paired benchmark design for
  nondeterministic agents; (2) verified defect injection — a variant runs only
  if the defect manifested and pixels are unchanged; (3) results per defect ×
  agent × model with intervals, including nulls; (4) `verity agent-check`,
  which pins an agent failure to a confirmed WCAG defect with zero wrong
  confirmations on the injected corpus.

## 2. Related work

Web-agent benchmarks (MiniWoB++, WebArena, VisualWebArena, BrowserGym);
observation-space studies; automated accessibility testing (axe-core and the
tools built on it, which by their vendors' own figures detect ~30–57% of WCAG
issues); LLM-based accessibility repair (detection and fix rates reported
without regression rates — §6.3).

## 3. Method

### 3.1 Agents
| Agent | Perceives | Acts by |
|---|---|---|
| tree | Chrome's accessibility tree, as indented text with element ids | element id / keyboard |
| browser-use | DOM interactive elements and their visible text | element id / keyboard |
| screen-reader | browse-mode announcements (name, role, states) + the focused element | keyboard only (enforced) |

All three share one control loop, a closed action vocabulary with an honest
escape (`report_infeasible`), a step cap, and a loop guard.

### 3.2 Tasks and success
**[RUN: final task count]** MiniWoB++ tasks across button, link, selection and
form families. Success is MiniWoB's own reward (time-discounted, > 0 on a
solve); vendored-app tasks use deterministic evaluators (URL, element state,
storage, app API, database) that must fail the start state and pass the
solved state before inclusion.

### 3.3 Defects and injection verification
Six defects in two families (pre-registration §4): name (`strip_name`,
`div_button`, `detach_label`) and keyboard/focus (`keyboard_trap`,
`remove_from_tab_order`, `outline_none`). Each is injected at page load and
verified before use: name defects by a change in the agent's own tree view,
keyboard defects by a Tab probe on clean vs defect pages; and every variant by
a pixel-identical screenshot. A variant that fails verification never runs.

### 3.4 Design and analysis (pre-registered)
Paired clean vs defect episodes on the same (task, agent, model, trial);
exact McNemar per cell with Holm–Bonferroni within H1; Bonett–Price
adjusted-Wald intervals; task-cluster bootstrap as sensitivity, with the
conservative result headlined; exclusions by rule (provider error, budget,
unverified injection, indeterminate evaluator), dropped with their pair. Run
order seeded (20261108); no peeking at success during the run; a hard budget
cap enforced before every model call.

### 3.5 Hypotheses
H1 name defects reduce tree-agent success; H2 DOM/visible-text agents are less
affected; H3 keyboard/focus defects hurt the screen-reader agent most; H4
accessible pages cost fewer tokens per success.

## 7. Limitations
MiniWoB++ pages are small; vendored apps are pending. Claude's API version
2026-10-21 accepts no sampling parameters, so frontier runs cannot be seeded —
their variance is measured, not controlled. The screen-reader agent simulates
announcements from Chrome's accessibility tree; it is not NVDA, JAWS or
VoiceOver. Contrast defects are excluded (a tree agent cannot perceive them).
A null result on a defect is reported as such.
